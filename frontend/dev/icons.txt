# The shell's icon set — the input to `npm run icons`.
#
# One line per icon:   <bootstrap-icons file name> = <mosaicast name> [*]
#
# The rename column is the point: call sites say `<Icon name="settings" />`, never the source
# family's spelling. Swapping icon families later is then a change to this file alone.
#
# A trailing `*` marks the icon PUBLIC: it is additionally emitted into `src/styles/icons.css` as a
# `--mc-icon-*` custom property. Those inherit across the shadow boundary, so plugins read them
# exactly as they read the colour tokens (ARCHITECTURE §12.3). **A published name is a contract with
# every installed plugin — add freely, rename never.**
#
# ## Why this list is larger than what core draws
#
# A plugin lives in its own repo and builds against a *released* core. If the icon it needs is not
# already published, its author cannot add one — they wait for a core release. So the set is
# provisioned ahead of demand, deliberately, and the groups below are aimed at the plugins we know
# about (bingo, stats, wiki) plus the obvious next one (polls). An icon nobody has used yet is not
# dead weight; it is the difference between a plugin author shipping this week or next quarter.
#
# The whole list ships whether an icon is used or not — `<Icon name>` resolves its drawing at
# runtime, so no bundler can prove a name unreachable, and the custom properties are declared on
# `:root` for everyone. Measured cost is roughly 160 B gzipped per icon across both artefacts. That
# is the deliberate trade for one coherent, always-available palette.
#
# Regenerate after every change:  npm run icons   (CI fails a PR where this file and the generated
# artefacts disagree).
